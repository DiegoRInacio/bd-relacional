O problema

E se não existisse banco de dados?

Um sistema de escola precisa guardar alunos, cursos e notas. Sem um SGBD, você teria que fazer tudo na mão:

  • inventar o formato dos arquivos;
  • escrever o código que lê e grava byte a byte;
  • impedir dois usuários de escrever ao mesmo tempo;
  • tratar queda de energia no meio da gravação;
  • e repetir isso no próximo sistema.
A solução

O SGBD entra no meio

SGBD = Sistema Gerenciador de Banco de Dados. Um programa, feito por outras pessoas, que fica entre a sua aplicação e os dados. Você diz o quê; ele resolve o como.

História

Antes do modelo relacional

Nos anos 60, os bancos eram hierárquicos (IBM IMS) ou em rede (CODASYL): registros ligados por ponteiros.

Para achar "as notas do João", o programador escrevia o caminho, passo a passo, seguindo ponteiros na mão.

Mudou a estrutura? Reescreva os programas.

História

1970 — Edgar F. Codd

Pesquisador da IBM, propõe o modelo relacional: os dados são apenas tabelas e você descreve o que quer — não o caminho até lá.

Navegacional ("abra isto, siga aquele ponteiro")  →  Declarativo ("me devolva os alunos com idade > 18"). O como vira problema do SGBD.

Anatomia de uma tabela

Fundamento

Regras de uma relação

  • A ordem das linhas não importa.
  • A ordem das colunas não importa — chame pelo nome.
  • Nenhuma linha se repete por inteiro.
  • Cada célula guarda um único valor (atômico).
É o que permite consultar os dados com álgebra — e é daí que vem o poder do SQL.
Formalização

O que é uma relação, formalmente

É um subconjunto do produto cartesiano dos domínios dos atributos:

r(R)  ⊆  dom(A₁) × dom(A₂) × ... × dom(Aₙ)

Para aluno(matricula, nome, idade):

aluno  ⊆  CHAR(8) × VARCHAR(30) × INTEGER

Uma linha concreta é uma tupla desse conjunto:

('20240001', 'Ana Prado', 19)   ∈   aluno
Conceito-chave

Como identificar uma linha?

Se nenhuma linha se repete, precisa haver algo que identifica cada tupla sem ambiguidade: a chave primária.

nome não serve — pode existir outra "Ana Prado". matricula serve.

Voltamos a isso na Aula 04, com PRIMARY KEY.

Conceito-chave

Tabelas se conectam

Para onde vamos

SQL em 30 segundos

-- 1. criar a estrutura
CREATE TABLE aluno (
    matricula CHAR(8)     PRIMARY KEY,
    nome      VARCHAR(30) NOT NULL,
    idade     INTEGER
);

-- 2. inserir dados
INSERT INTO aluno VALUES ('20240001', 'Ana Prado', 19);

-- 3. consultar
SELECT nome FROM aluno WHERE idade >= 18;
Você descreve o resultado; o PostgreSQL descobre como entregá-lo.
