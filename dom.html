Visão geral

O que é normalização

Um processo de reorganizar as tabelas para reduzir redundância e evitar anomalias — feito em etapas chamadas formas normais.

Cada forma normal só é checada depois que a anterior está OK.
Motivação

As três anomalias

Exemplo do dia

A planilha de pedidos

Cada linha é um item de um pedido — um pedido pode ter vários produtos.

Chave: o par (id_pedido, id_prod) identifica cada linha.
Ferramenta

Dependência funcional

X → Y lê-se "X determina Y": sabendo o valor de X, o valor de Y é sempre o mesmo.

As dependências desta planilha:

  • id_cli → nome_cliente
  • id_prod → nome_produto, preco
  • id_pedido → id_cli
  • (id_pedido, id_prod) → qtd
1ª Forma Normal

1FN — um valor por célula

  • cada célula guarda um único valor (atômico);
  • sem grupos repetidos de colunas;
  • cada linha identificável (tem chave).

Aqui o problema é telefone_cliente: guarda dois números.

2ª Forma Normal

2FN — nada de dependência parcial

Estar em 1FN + toda coluna não-chave depende da chave inteira, não só de um pedaço dela.

A chave é (id_pedido, id_prod). Mas:

  • nome_produto, preco dependem só de id_prod;
  • id_cli, nome_cliente dependem só de id_pedido.

São dependências parciais → violam a 2FN.

2ª Forma Normal

2FN aplicada: três tabelas

3ª Forma Normal

3FN — nada de dependência transitiva

Estar em 2FN + coluna não-chave não pode depender de outra coluna não-chave.

Na tabela Pedido: nome_cliente depende de id_cli, que depende de id_pedido. É uma dependência transitiva.

3ª Forma Normal

3FN aplicada: o esquema final

Notação pé de galinha — || lê "um" · o{ / |{ lê "vários" (zero-ou-muitos / um-ou-muitos).

Resultado

Antes × depois

Antes — 1 tabela
  • "João Silva" repetido em 3 linhas
  • trocar 1 telefone = corrigir várias linhas
  • apagar pedido some com o cliente
Depois — 5 tabelas
  • cada cliente/produto guardado uma vez
  • trocar o telefone = 1 linha
  • cliente e produto existem sozinhos
Custo: para "ver" o pedido completo de novo, é preciso juntar as tabelas (JOIN).
Na prática

Inserindo nas tabelas normalizadas

-- ordem: pais antes dos filhos
INSERT INTO cliente (id_cli, nome_cliente) VALUES
  ('C1','João Silva'), ('C2','Maria Oliveira');

INSERT INTO produto (id_prod, nome_produto, preco) VALUES
  ('P1','Notebook',3000), ('P2','Mouse',80);

INSERT INTO pedido (id_pedido, id_cli) VALUES (1,'C1');

INSERT INTO item_pedido (id_pedido, id_prod, qtd) VALUES
  (1,'P1',1), (1,'P2',2);
Na prática

Juntando tudo de novo

A "planilha" original volta com um SELECT + JOIN:

SELECT p.id_pedido, c.nome_cliente,
       pr.nome_produto, i.qtd
FROM   pedido      p
JOIN   cliente     c  ON c.id_cli = p.id_cli
JOIN   item_pedido i  ON i.id_pedido = p.id_pedido
JOIN   produto     pr ON pr.id_prod = i.id_prod;

JOIN é o tema da Aula 07.

Equilíbrio

Normalizar sempre?

Normalizar (regra geral)
menos redundância, menos anomalia, dados consistentes. É o default.
Desnormalizar (exceção)
duplicar algo de propósito para evitar JOINs caros em relatórios muito acessados.
Desnormalização é decisão consciente de desempenho — não é "esquecer de normalizar".
