Confiabilidade

ACID — a promessa das transações

Como garante

WAL — escreve a intenção primeiro

Antes de mexer nas tabelas, o PostgreSQL grava o que vai fazer num registro sequencial em disco: o WAL (Write-Ahead Log).

Se o servidor cair no meio da operação, na volta ele relê o WAL e refaz o que faltou (REDO). Nada de banco corrompido.

Concorrência

MVCC — ninguém fica esperando

Controle de Concorrência Multiversão: cada transação enxerga um retrato (snapshot) do banco. Quem lê não trava quem escreve, e vice-versa.

Desempenho

Índices — achar sem varrer tudo

Sem índice, buscar um valor = ler a tabela inteira (Seq Scan).

Com índice, o banco vai direto às linhas certas (Index Scan).

Tipos no PostgreSQL: B-Tree (padrão, para =, <, >, ordenação), GIN (texto, JSON), GiST/BRIN (dados espaciais, faixas).

Primeiro contato

-- no terminal psql, ou no editor do DBeaver / pgAdmin:

SELECT version();            -- qual PostgreSQL está rodando
SELECT current_user;         -- com qual usuário estou conectado
SELECT current_database();   -- em qual banco

-- criar um banco de dados novo
CREATE DATABASE escola;

-- no psql:  \l  lista bancos   ·   \dt  lista tabelas   ·   \q  sai
Na próxima aula a gente projeta um banco de verdade e começa a criá-lo.
