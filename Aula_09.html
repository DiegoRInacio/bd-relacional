Conceito

O que é uma view

Uma consulta salva com um nome. Você usa a view como se fosse uma tabela, mas ela não guarda dados — a cada consulta, o SELECT por trás roda de novo.

A view é uma tabela virtual: aparência de tabela, conteúdo de consulta.
Motivação

Para que servem

Simplificar
esconde um JOIN grande atrás de um nome curto
Segurança
expõe só as colunas/linhas que o usuário pode ver
Manutenção
a lógica fica num lugar só — mudou a regra, mudou a view
Padronização
todo mundo consulta o "faturamento" da mesma forma
Sintaxe

Criar e consultar

-- criar
CREATE VIEW pedidos_pagos AS
SELECT c.nome, p.id, p.valor
FROM   cliente c
JOIN   pedido  p ON p.id_cliente = c.id
WHERE  p.status = 'pago';

-- usar: como qualquer tabela
SELECT * FROM pedidos_pagos WHERE valor > 200;

-- trocar a lógica sem recriar
CREATE OR REPLACE VIEW pedidos_pagos AS SELECT ... ;
Exemplo · simplificar

Um nome no lugar do JOIN

Sem view — todo relatório repete o JOIN:

SELECT c.nome, p.valor
FROM cliente c JOIN pedido p
  ON p.id_cliente = c.id
WHERE p.status = 'pago' AND c.cidade = 'SP';

Com a view pedidos_pagos:

SELECT * FROM pedidos_pagos
WHERE cidade = 'SP';
Exemplo · agregação

View de resumo

CREATE VIEW total_por_cliente AS
SELECT c.nome,
       COUNT(p.id)              AS pedidos,
       COALESCE(SUM(p.valor),0) AS total
FROM   cliente c
LEFT JOIN pedido p ON p.id_cliente = c.id
GROUP BY c.nome;
SELECT * FROM total_por_cliente
ORDER BY total DESC;

Comportamento

A view sempre reflete a tabela

Não existe "atualizar a view" — ela roda o SELECT toda vez. (A exceção é a view materializada, no próximo slide.)
Uso · segurança

Mostrar só uma parte

CREATE VIEW cliente_publico AS
SELECT id, nome, cidade      -- some cpf, telefone, email
FROM   cliente;

-- o usuário recebe acesso à VIEW, não à tabela
GRANT SELECT ON cliente_publico TO atendente;
REVOKE ALL   ON cliente        FROM atendente;

Também dá para filtrar linhas: WHERE ativo = TRUE.

View materializada

Quando materializar

Vale a pena quando o SELECT é pesado (agrega milhões de linhas), é consultado o tempo todo, e os dados podem estar alguns minutos atrasados sem problema — um dashboard, um relatório mensal.

REFRESH MATERIALIZED VIEW CONCURRENTLY
       faturamento_mensal;   -- não trava as consultas
Limitações

Dá para gravar por uma view?

View simples → sim
uma view de uma tabela, sem JOIN/GROUP BY/DISTINCT, aceita INSERT/UPDATE/DELETE — o banco repassa pra tabela base.
View complexa → não direto
com JOIN ou agregação, o banco não sabe onde gravar. Solução: um trigger INSTEAD OF (Aula 08) que faz o INSERT na tabela certa.
Na dúvida, trate a view como só leitura.
