Constraints

Seis regras para a integridade

Constraints são condições que o dado tem que satisfazer — o banco rejeita o que não passa.

NOT NULL
a coluna não pode ficar vazia
DEFAULT
valor automático quando não informado
PRIMARY KEY
identifica a linha: única + não nula
UNIQUE
não repete valor nessa coluna
CHECK
o valor obedece a uma condição
FOREIGN KEY
aponta para uma linha válida de outra tabela
Constraints

NOT NULL e DEFAULT

NOT NULL — obriga a coluna a ter valor. Sem ele, a coluna aceita NULL ("não sei / não informado").

DEFAULT — se você não informar, o banco preenche sozinho.

CREATE TABLE conta (
    id          SERIAL PRIMARY KEY,
    titular     VARCHAR(100) NOT NULL,
    saldo       NUMERIC(15,2) NOT NULL DEFAULT 0,
    aberta_em   DATE          DEFAULT CURRENT_DATE,
    ativa       BOOLEAN       DEFAULT TRUE
);

INSERT INTO conta (titular) VALUES ('Ana');
-- saldo = 0, aberta_em = hoje, ativa = true
Constraint · PRIMARY KEY

A chave que identifica a linha

  • única — não há duas linhas com o mesmo valor;
  • não nula — sempre preenchida;
  • uma por tabela (pode ser composta por várias colunas).
CREATE TABLE curso (
    id   SERIAL PRIMARY KEY,
    nome VARCHAR(100) NOT NULL
);
Constraint · SERIAL

SERIAL — o id se preenche sozinho

SERIAL = coluna inteira que o PostgreSQL incrementa automaticamente a cada inserção. Combina com PRIMARY KEY.

CREATE TABLE cliente (
    id   SERIAL PRIMARY KEY,
    nome VARCHAR(100) NOT NULL
);

INSERT INTO cliente (nome) VALUES ('Ana');
INSERT INTO cliente (nome) VALUES ('Beto');
Constraint · UNIQUE

UNIQUE — sem repetição

Garante que a coluna não tenha valores repetidos — mas, ao contrário da PK:

  • uma tabela pode ter várias colunas UNIQUE;
  • UNIQUE aceita NULL (um ou mais, depende do SGBD).
CREATE TABLE usuario (
    id    SERIAL PRIMARY KEY,
    email VARCHAR(120) UNIQUE NOT NULL,
    cpf   CHAR(11)     UNIQUE
);
Constraint · CHECK

CHECK — o valor tem que fazer sentido

CREATE TABLE produto (
    id     SERIAL PRIMARY KEY,
    nome   VARCHAR(100) NOT NULL,
    preco  NUMERIC(10,2) CHECK (preco > 0),
    estoque INT          CHECK (estoque >= 0),
    status VARCHAR(10)
           CHECK (status IN ('ativo','inativo'))
);
Constraint · FOREIGN KEY

FOREIGN KEY — o vínculo entre tabelas

FOREIGN KEY

E se apagarem o "pai"?

Você escolhe o comportamento na hora de criar a FK:

Juntando tudo

Um esquema com todas as constraints

CREATE TABLE curso (
    id   SERIAL       PRIMARY KEY,
    nome VARCHAR(100) NOT NULL UNIQUE
);

CREATE TABLE aluno (
    id         SERIAL       PRIMARY KEY,
    nome       VARCHAR(100) NOT NULL,
    email      VARCHAR(120) UNIQUE NOT NULL,
    idade      INT          CHECK (idade >= 16),
    ativo      BOOLEAN      NOT NULL DEFAULT TRUE,
    curso_id   INT          REFERENCES curso(id) ON DELETE RESTRICT
);
INSERT INTO

Duas formas de inserir

Com as colunas (recomendada)

INSERT INTO aluno (nome, email, idade)
VALUES ('Ana', 'ana@ex.com', 19);

Sem as colunas (frágil)

INSERT INTO aluno
VALUES (1, 'Ana', 'ana@ex.com', 19, TRUE, 10);
Sempre liste as colunas. Se alguém adicionar ou reordenar uma coluna da tabela, a forma "sem colunas" quebra silenciosamente ou grava no lugar errado.

A forma com colunas também deixa o banco preencher SERIAL e DEFAULT por você.

INSERT INTO

DEFAULT e várias linhas de uma vez

-- deixar o DEFAULT agir (não informa a coluna)
INSERT INTO aluno (nome, email) VALUES ('Beto', 'beto@ex.com');
-- ativo = TRUE (default), id gerado pelo SERIAL

-- várias linhas em um comando só (mais rápido e legível)
INSERT INTO curso (nome) VALUES
  ('Eng. de Software'),
  ('Medicina'),
  ('Direito');
Um INSERT com várias linhas roda como uma transação: se uma linha falha, nenhuma entra.
INSERT INTO

Inserir a partir de uma consulta

Em vez de VALUES, o INSERT pode receber um SELECT: copia dados de uma tabela para outra, já filtrados.

INSERT INTO aluno_formado (nome, email)
SELECT nome, email
FROM   aluno
WHERE  idade >= 22;
Boas práticas

A ordem importa

Por causa das FKs, insira o "pai" antes do "filho":

  1. curso (não depende de ninguém)
  2. aluno (depende de curso)

Outras práticas:

  • listar as colunas no INSERT;
  • conferir formato e restrições antes;
  • agrupar cargas grandes em transação.
