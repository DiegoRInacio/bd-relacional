Conceito

O que é uma trigger

Um bloco de código que o banco dispara sozinho toda vez que acontece um INSERT, UPDATE ou DELETE numa tabela.

Ninguém "chama" a trigger — ela reage ao evento sozinha.
Motivação

Para que servem

Auditoria
registrar quem alterou o quê e quando
Automação
preencher campos como data_modificacao sozinho
Integridade
manter tabelas relacionadas consistentes
Regras de negócio
bloquear uma operação inválida antes de gravar
Estrutura

Uma trigger tem duas partes

Momento

BEFORE, AFTER e INSTEAD OF

MomentoRodaServe para
BEFOREantes de gravarvalidar, bloquear ou ajustar NEW
AFTERdepois de gravarlog / auditoria, atualizar outra tabela
INSTEAD OFno lugar da operaçãotornar uma view "gravável"
Regra prática: validou/mudou o dado → BEFORE. Reagiu ao que já foi gravado → AFTER.
Evento e escopo

O que dispara e com que frequência

Evento
INSERT · UPDATE · DELETE
(pode combinar: AFTER INSERT OR UPDATE)
FOR EACH ROW
roda uma vez por linha afetada. É o que quase sempre se usa.
FOR EACH STATEMENT
roda uma vez por comando, mesmo que ele afete 1000 linhas.
Dentro da função

NEW e OLD — os dados da linha

A função recebe registros especiais:

EventoOLDNEW
INSERT—a linha nova
UPDATEvalores antigosvalores propostos
DELETEa linha apagada—

Acesso por coluna: NEW.preco, OLD.status.

Exemplo do dia

O banco de vendas

log_vendas não tem FK e só recebe dados pela trigger — por quê no próximo slide.

Passo 1 · a função

A função log_venda()

CREATE OR REPLACE FUNCTION log_venda()
RETURNS TRIGGER AS $$
DECLARE
    v_nome vendedor.nome%TYPE;
BEGIN
    SELECT nome INTO v_nome
    FROM   vendedor WHERE id_vendedor = NEW.id_vendedor;

    INSERT INTO log_vendas
        (id_venda, id_vendedor, nome_vendedor, quantidade, data_log)
    VALUES
        (NEW.id_venda, NEW.id_vendedor, v_nome, NEW.quantidade, NOW());

    RETURN NEW;    -- obrigatório; devolve a linha sem alterar
END;
$$ LANGUAGE plpgsql;
A função não recebe parâmetros e retorna TRIGGER. Além dos IDs, ela grava o nome do vendedor da época (snapshot).
Boas práticas

Como projetar a tabela de log

Sem FK
a referência é lógica (int, não REFERENCES). O log tem que sobreviver se a venda for apagada.
Snapshot dos valores
guarde também o que era na hora (nome_vendedor, valor) — o log continua legível mesmo se a origem mudar.
Append-only
só a trigger insere. REVOKE UPDATE, DELETE ON log_vendas FROM ... — ninguém edita ou apaga.
Nunca deleta linha de log
uma tabela de auditoria só cresce. Se precisar liberar espaço, arquiva — não apaga.
FK com ON DELETE CASCADE num log destrói a auditoria: apagou a venda, sumiu o registro dela.
Passo 2 · o gatilho

Ligando a função à tabela

O CREATE TRIGGER não tem lógica nenhuma — ele só diz quando o banco deve chamar a função que você criou no passo 1.

Nome por convenção começa com trg_. Para remover: DROP TRIGGER trg_log_venda ON vendas;
Funcionando

Em ação

BEFORE · bloquear

Impedir uma operação inválida

CREATE OR REPLACE FUNCTION checa_estoque()
RETURNS TRIGGER AS $$
BEGIN
    IF NEW.quantidade > (SELECT estoque FROM produto
                          WHERE id_produto = NEW.id_produto) THEN
        RAISE EXCEPTION 'Estoque insuficiente para o produto %',
                        NEW.id_produto;
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_checa_estoque
BEFORE INSERT ON vendas
FOR EACH ROW EXECUTE FUNCTION checa_estoque();
UPDATE · OLD e NEW

Registrar o que mudou

CREATE OR REPLACE FUNCTION log_preco()
RETURNS TRIGGER AS $$
BEGIN
    IF NEW.preco <> OLD.preco THEN           -- só se o preço realmente mudou
        INSERT INTO log_preco (id_produto, preco_antigo, preco_novo, data_log)
        VALUES (OLD.id_produto, OLD.preco, NEW.preco, NOW());
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_log_preco
AFTER UPDATE ON produto
FOR EACH ROW EXECUTE FUNCTION log_preco();
Cuidados

Onde as triggers mordem

Desempenho
rodam a cada linha — um INSERT de 10 mil linhas dispara 10 mil vezes.
Lógica escondida
o comando "simples" faz mais do que parece — difícil de depurar.
Recursão
trigger em A que mexe em B, que tem trigger que mexe em A → loop.
Manutenção
poucas, com nome claro (trg_...) e comentadas.
Resumo

Trigger ou outra coisa?

NecessidadeFerramenta
valor obrigatório / padrão / faixa simplesNOT NULL, DEFAULT, CHECK

Trigger é para o que precisa acontecer independente de quem fez a operação.
