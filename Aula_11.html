API RESTful vs. SQL Direto

Visão geral

Duas formas de chegar aos dados

Ou a aplicação fala direto com o PostgreSQL, ou passa por uma API que fica no meio do caminho.

A API é uma camada no meio: só ela toca o banco, e centraliza regras e segurança.
Conceito

O que é uma API REST

Uma interface pela web (HTTP) onde cada "coisa" do sistema é um recurso com uma URL, e você opera nele com os métodos HTTP.

Coleção
GET /clientes → lista todos
Item
GET /clientes/7 → um cliente
Criar
POST /clientes + JSON no corpo
Resposta
JSON + um código (200, 201, 404...)

SQL direto

Falar direto com o banco

import psycopg2

conn = psycopg2.connect(
    dbname="loja", host="localhost",
    user="ana", password="S3nh@")

cur = conn.cursor()
cur.execute("SELECT nome, cidade FROM cliente")
for nome, cidade in cur.fetchall():
    print(nome, cidade)

conn.close()

Simples e poderoso, mas:

  • cada cliente precisa da senha do banco;
  • a regra de negócio fica espalhada em cada app;
  • o banco fica exposto na rede.

Ferramenta

FastAPI + Swagger

FastAPI é um framework Python para construir APIs. De brinde, ele gera a documentação interativa (Swagger UI) em /docs — dá para testar cada endpoint pelo navegador.

pip install fastapi uvicorn psycopg2-binary
uvicorn main:app --reload
# → http://localhost:8000/docs
O que é o Swagger? Um padrão (hoje chamado OpenAPI) para descrever uma API — quais endpoints existem, o que cada um recebe e devolve. Dessa descrição, o Swagger UI monta uma página onde você lê a documentação e executa as chamadas pelo navegador. O FastAPI gera essa descrição sozinho a partir das suas funções e modelos Python.
Endpoint de leitura

GET /clientes

from fastapi import FastAPI, Depends
import psycopg2

app = FastAPI(title="API Loja")

@app.get("/clientes")
def listar_clientes(conn = Depends(get_conn)):
    with conn.cursor() as cur:
        cur.execute("SELECT id, nome, cidade FROM cliente ORDER BY nome")
        cols = [c.name for c in cur.description]
        return [dict(zip(cols, row)) for row in cur.fetchall()]
# resposta: [{"id":1,"nome":"Ana","cidade":"SP"}, ...]  + código 200
Endpoint de escrita

POST /clientes

from pydantic import BaseModel

class ClienteIn(BaseModel):        # valida o JSON de entrada
    nome: str
    cidade: str

@app.post("/clientes", status_code=201)
def criar_cliente(c: ClienteIn, conn = Depends(get_conn)):
    with conn.cursor() as cur:
        cur.execute("INSERT INTO cliente (nome, cidade) VALUES (%s, %s) RETURNING id",
                    (c.nome, c.cidade))
        novo_id = cur.fetchone()[0]
    conn.commit()
    return {"id": novo_id, **c.model_dump()}
%s + tupla = parâmetro, não concatenação — é o que evita SQL injection.
Swagger UI

Testando pelo navegador

Em localhost:8000/docs o FastAPI mostra cada endpoint, deixa preencher os parâmetros e ver a resposta — sem escrever nenhum código de cliente.

Usuário e senha

A API pede credencial

from fastapi.security import HTTPBasic, HTTPBasicCredentials
from fastapi import HTTPException

security = HTTPBasic()

def get_conn(cred: HTTPBasicCredentials = Depends(security)):
    try:
        conn = psycopg2.connect(
            dbname="loja", host="localhost",
            user=cred.username, password=cred.password)
    except psycopg2.OperationalError:
        raise HTTPException(401, "usuário ou senha inválidos")
    try:
        yield conn
    finally:
        conn.close()
Juntando com a Aula 10

A API conecta COMO o usuário

A API não reinventa o controle de acesso — as permissões da Aula 10 valem sozinhas. O auditor_cli consulta, mas não cria.
Roteiro de teste

Testando no Swagger

  1. rodar uvicorn main:app --reload;
  2. abrir localhost:8000/docs;
  3. clicar em Authorize e informar auditor_cli / senha;
  4. GET /clientes → "Try it out" → Execute → 200 + a lista;
  5. POST /clientes → preencher o JSON → Execute → 403 (a role só tem SELECT);
  6. repetir com recepcionista_cli → o POST agora dá 201.
Decisão

Quando cada um

API REST
  • vários sistemas consomem os dados
  • web / mobile / parceiros externos
  • regra de negócio e segurança centralizadas
  • o banco não deve ficar exposto
SQL direto
  • ETL, BI, carga de dados
  • relatórios internos e scripts do DBA
  • consultas ad-hoc, migração
  • performance máxima, ambiente controlado
Na prática, os dois convivem: a API para o dia a dia, SQL direto para o back-office.
Resumo

O que levar

  • a API é uma camada HTTP entre quem consome e o banco;
  • método HTTP ↔ CRUD ↔ SQL (GET/SELECT, POST/INSERT...);
  • FastAPI gera o Swagger (/docs) para testar tudo pelo navegador;
  • com HTTP Basic, a API pode conectar no banco como o próprio usuário — e as permissões da Aula 10 valem automaticamente;
  • SQL direto continua sendo o melhor para ETL, BI e trabalho do DBA.
